# UI 审查（2026-10-12）

范围为本地 Web，桌面 Chromium 和手机尺寸浏览器模拟。页面几何检查、真实操作和截图检查分别记录；几何通过不代表流程可用。

| 编号 | 优先级 | 页面与问题 | 用户影响 | 建议 |
| --- | --- | --- | --- | --- |
| UI-01 | P1 | 批次详情侧栏遮住阶段发布确认框 | 主流程确认按钮不能点击 | 将确认框放在当前侧栏之上，统一叠层和焦点栈 |
| UI-02 | P1 | 教师认证后详情仍显示待审核和通过认证 | 不清楚操作是否成功，可能重复操作 | 用保存结果刷新当前详情或明确关闭详情并反馈成功 |
| UI-03 | P2 | 三角色工作台和工作流小字号灰色文字对比不足 | 标签、说明和未激活入口不容易看清 | 调整共享文字颜色；同时检查背景颜色，保持小字对比度至少 4.5:1 |
| UI-04 | P2 | 手机管理员工作台四个统计卡片竖排，主操作接近首屏底部 | 首次打开先看到大量数字，操作入口被推到下面 | 用紧凑的两列统计，优先呈现待处理事项和主操作 |
| UI-05 | P2 | 教师待办重复标题、空短表单占很高的整块面板 | 页面大量留白，创建任务的层级不清晰 | 保留一个页面标题；短创建表单采用紧凑弹窗或按内容高度布局 |
| UI-06 | P2 | 规范作用域绑定要求填写组织 ID | 教师难以从组织名称判断应填写什么 | 用有名称的组织选择器，内部 ID 留在数据层 |
| UI-07 | P2 | 归档完成列表仅显示内部 submission ID | 管理员难以辨认对应论文和学生 | 展示论文题目、学生、阶段和提交编号，内部 ID 不作主要标签 |
| UI-08 | P1 | 审核建议类型框无可访问名称，两个正文表格滚动区不能聚焦 | 屏幕阅读器难识别用途；键盘难操作表格 | 明确控件标签，给表格滚动区添加可聚焦入口和名称 |

UI-01、UI-02 有运行时操作证据；UI-03 有 axe-core 4.14.0 自动扫描证据；UI-04、UI-05 是截图确认的体验问题；UI-06 有规范创建流程截图。UI-07 由归档完成截图确认。提交记录的三个功能问题见 Bug 条目。

自动扫描共覆盖 9 个场景：登录、三角色工作台、三角色工作流、新建论文弹窗、真实审核详情。登录和新建论文弹窗没有自动违规；其余 6 场景均命中 color-contrast，共 23 个对比度节点实例；审核详情另有 2 个 scrollable-region-focusable、1 个 select-name 节点，总计 26 个实例；共享问题不重复算独立缺陷。创建论文弹窗的 Tab、Shift+Tab、Escape 与关闭后焦点恢复通过；实际审核的退回和通过也可用 Tab 到达。自动扫描和有限键盘测试不能替代全面无障碍验收。

已有改进也已回归：新建论文现在为居中紧凑弹窗；模板导入长标题换行且标题层级清楚，技术映射列不再挤占预览。`compact-previews.spec.ts` 桌面/手机项目的 12 项通过。桌面多尺寸页面扫描通过，但这不能证明每个详情状态及弹窗叠层通过。

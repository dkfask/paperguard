## 本地代码做了什么

此前 worker 已在站内 outbox 之后调用 `deliver_wechat_push`，但产品化缺口是：

1. 订阅卡片 `page` 固定 `/pages/tasks/index`，审核结果/待审/批注无法落到匹配页。
2. 截止/逾期催办只在创建时看参与者状态，发送前不再复核；已通过或延期后旧催办仍可能发微信。
3. 订阅授权只在提交成功页，不在「确认正式提交」手势上。
4. compose 未透传 `PAPERGUARD_WECHAT_SUBSCRIBE_TEMPLATES`，未配置时只能走站内信，部署侧无法从环境注入模板映射。

本切片改动：

- `subscribe_page` 按事件落到提交详情 / 审阅 / 批注 / 任务页。
- `should_skip_stale_push` 在发送前跳过已通过/退出/撤回/归档，以及延期后不再逾期或不再临近 72 小时的催办；跳过记 `skipped_stale`，不消耗配额。
- 无绑定、无配额、43101、发送失败仍只降级站内信，不阻断业务。
- 抽出 `miniprogram/src/utils/subscribe.ts`；提交确认点击先请求一次性订阅（未配置模板静默），成功页仍可补授权。
- `docker-compose.yml` / `docker-compose.staging.yml` 从环境透传模板 JSON，源码不写凭据或模板字面量。

未回滚学院管理员桌面端与 MP1/MP2 未提交修复，也未提交 git。

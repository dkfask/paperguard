# 浏览器控制超时排查记录

初次记录：2026-10-14 22:42，Asia/Shanghai；续记：2026-10-15。

**SYS-A曾通过Chrome原生窗口完成网页登录，但网页控制整体尚未恢复。** 后续对Chrome标签页调用 `getTab` 再次出现 `js execution timed out; kernel reset`；独立标签页路由仍不可用。之前的登录证据只证明当时的SYS-A登录页，不代表当前页面导航或完整网页UAT通过。

## 故障与定位

对当前内置浏览器登录页调用 `cua.getTab(..., {browser: 'iab'})`，约30秒后报 `js execution timed out; kernel reset`。客户端日志同时记录：

```text
No ChatGPT browser route is available for browser session 01a139c6-0c36-7662-925e-fa89abace3b5
```

主分类为 `ENVIRONMENT`：当前聊天的内置浏览器控制路由不可用。该错误发生在客户端控制链路，不能据此判定 PaperGuard 登录失败。日志未证明路由缺失的底层原因。

## 验证与恢复

| 检查 | 实测结果 | 结论 |
|---|---|---|
| 基础 JavaScript 运行时 | 返回 `runtimeAlive=true` | 正常 |
| 当前聊天重新打开浏览器面板 | 工具返回 `queued` | 尚未实际完成重绑 |
| 显式重置 CUA 内核 | 返回 `js kernel reset` | 重置成功，不证明路由恢复 |
| 原生控制 ChatGPT/Codex 本体 | 被工具安全策略拒绝 | 保留边界，未重试或绕过 |
| 直接选择 Google Chrome | 1.30秒内读到生产登录表单 | 原生浏览器通道可用 |
| 输入专用 SYS-A 账号并正常登录 | 跳转 `/workspace`；显示测试身份、角色工作台和退出按钮 | 网页登录成功 |
| 读取登录后导航 | 0.11秒内取得学校运营菜单 | 后续网页读取可用 |
| 后续绑定 Chrome 标签页 `getTab` | 约12秒后 `js execution timed out; kernel reset`；之后可见状态不是目标业务页 | 同一客户端控制故障复现；该尝试未验证PaperGuard页面 |

## 续查结论与临时处置

现有证据仍将故障定位在Codex本地浏览器控制路由，不是PaperGuard登录响应。重复执行同一个 `getTab` 请求不会修复缺失路由，反而再次重置执行内核，因此本轮停止重试。之前的 `cua.getApp('com.google.Chrome')` 原生窗口登录是有效的历史UI证据；但当前浏览器控制不稳定，不能据此声称后续页面流程已恢复。

为避免继续被控制路由拖住，合成业务流程继续通过已验证的SSH回环API执行，并明确标记 `ui_verified:false`；需实际页面观察的场景保持未完成。恢复完整UI测试需要Codex客户端为当前任务恢复浏览器会话路由，或由受控原生Chrome窗口重新建立可验证的页面操作。当前会话不能安全地修改/重启Codex或Chrome客户端来修复该路由。

本轮没有改客户端文件、认证路由缓存、系统安全设置或生产配置，也没有重启应用。

内置浏览器仍需客户端侧进一步处理；本轮 UAT 可以沿已验证的 Chrome 通道继续。原始个人浏览器外壳和密码未写入测试报告。

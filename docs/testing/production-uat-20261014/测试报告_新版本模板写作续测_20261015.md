## 4. 测试问题与处置

1. `TEST-DEFECT`：首轮等待导出响应未考虑 `?force=false`，且把预期拒绝码写成 422；同版本源码与页面均确认实际契约为 409。保留首轮失败，修正响应匹配后在同一项目继续，没有新建重复论文。
2. `TEST-DEFECT`：一次用 API 撤销会话后，页面仍暂存旧认证状态，产生三个预期之外的 401；当时已完成八个页面检查点。后续用全新浏览器会话独立验证重新登录和内容恢复，第九点通过且无 API 错误。没有将该脚本问题算作产品保存失败。
3. `DATA-PRECONDITION`：首次权限脚本假定 T-A 可直接读新建独立稿，实际 403。代码要求项目教师绑定或同批次指导关系；本次新稿尚未建立该交接前置。该项留为未完成，没有放宽服务端权限或把拒绝改成成功断言。其他三类越权账号独立完成负向检查。
4. `ENVIRONMENT`：初始本地渲染缺中文；DOCX 与 PDF 文本层均有完整中文。只给渲染器增加任务临时 Fontconfig 配置后，同一 DOCX 的中文恢复，未改文件字节或生产环境。十页最终图像已逐页检查。

# PaperGuard 生产角色闭环测试策略

本策略配套 [生产环境全角色测试计划书](生产环境全角色测试计划书.md)，范围为系统级黑盒测试。单元与集成测试属于开发侧保障，尚未在本轮复核；生产验收结论须以实际部署版本和真实操作为依据。本文件是规划产物，所有运行结果均未执行。

## Risk Map

评级采用影响与可能性各 1—5 分，乘积 20—25 为 Critical、10—19 为 High、4—9 为 Medium、1—3 为 Low。以下分值是基于功能复杂度和历史线索的规划判断，不代表当前生产存在对应缺陷，也不代表实测发生概率。证据级别 E2 表示本地源码/文档阅读；风险状态均为 hypothesis。

```yaml

    dimension: 权限
    impact: 5
    likelihood: 3
    level: High
    evidence: { level: E2, source: "backend/app/api/process_records.py:117", confidence: medium }
    description: 多角色与指导关系共同决定材料访问和审批，错误授权可能泄露论文或越权审批。
    status: hypothesis
  - id: R2
    feature: 多阶段与多轮审核
    dimension: 状态流转
    impact: 4
    likelihood: 3

    evidence: { level: E2, source: "backend/app/domain/workflow_states.py:29", confidence: medium }
    description: 提交、退回、撤回、通过和归档存在多条转换，错误状态可能阻断论文流程。

  - id: R3
    feature: 正文与提交快照

  - id: R4

  - id: R5

    feature: 角色入口与界面交接

    likelihood: 3

    description: 不同角色页面和深链接可能可见但不可操作，接口成功不足以保证用户能完成任务。
    status: hypothesis
```

R1—R5 优先安排主线及关键负向场景，提议列为 P0/P1；R6 提议列为 P1。最终用例优先级在场景细化时确定。风险编号用于追溯，正式用例通过 `risk_ref` 反查，不把本计划的场景包当成已经执行的原子用例。

深度为计划覆盖量，不是完成状态。`ready` 仅表示本地代码审查输入具备；所有生产运行轴仍为 blocked，待计划书准入条件补齐。上述 full 仅指经确认的单学校业务范围，不能解释为全资源多租户、全平台渗透或全部故障组合已覆盖。

G 级工具扫描用于生成线索，随后人工核对 README、角色路由、材料权限、工作流状态、AI 操作和历史未决项。扫描包含历史脚本与生成文件，命中数量不能当作缺陷数量；扫描未检出国际化不构成排除依据，本轮已从实际 `frontend/src/i18n.js` 补入。迁移因任务边界明确排除，不是因代码没有迁移功能。

## 足够性与停止条件

| 轴 | 本轮计划动作 | 完成状态与停止条件 |
|---|---|---|
| functional | 角色功能清单全登记，F/AI/X 场景全部有归属 | 未执行；确认范围内条目全部有证据或明确未完成状态 |
| boundary | 截止、必填、附件、候选版本及文本限制 | 未执行；正常值、关键边界和恢复路径均有结果 |
| permission | 角色×行为×测试资源归属矩阵 | 未执行；矩阵每格有允许/拒绝证据，缺账号仍保留阻塞格 |
| state | 主流程合法与非法转换、两轮修改 | 未执行；每条纳入范围的边均记录，不因首次通过停止 |
| data_consistency | 草稿/快照/批注/文件/统计交叉核对 | 未执行；所有关键交接对象能对账 |
| regression | 主流程和历史风险复测锚点 | 未执行；绑定被测版本，不复用旧版本绿灯 |
| performance | 分页、N+1、缓存依赖、锁及后台积压的局部源码审查 | 待执行；给出带源码位置的清单。本轮不产生产容量结论；主流程可记录耗时，未定阈值时不判性能合格 |
| security_business | 敏感响应/日志检查、获准合成输入的业务安全抽查 | 受阻；不与权限矩阵重复统计；不探测真实用户对象 |
| reliability | 超时、重试、未知结果和恢复后的状态一致性 | 受阻；生产自然错误与可控环境注入分开结论 |
| concurrency | 双标签保存、重复提交、撤回/审批竞争 | 受阻；每个竞争点核对最终唯一结果与历史记录 |
| compatibility | 已确认的浏览器/设备逐项跑主流程 | 受阻；缺设备列 BLOCKED；微信真机独立关闭 |
| accessibility | 关键页 axe 扫描与焦点/标签抽查 | 受阻；保留客观违规列表和人工复核结论 |
| visual | 登录、工作台、写作、审阅和归档截图存档 | 受阻；人工检查遮挡、溢出、错误态及角色信息 |
| i18n | 目标语言核心流程、时间显示及中英文内容抽查 | 受阻；语言范围确认后逐项记录 |
| migration | 本轮不执行 | 排除理由已记录，后续升级另建计划 |
| contract_integration | 实际供应商成功路径与隔离异常双层验证 | 受阻；真实调用和 mock 证据分开，未配置不写通过 |

以上为后续用例编写的输入，不是执行授权。按《计划书》中的角色、测试对象和预期拆分原子用例，并附 `risk_ref`；业务安全、可靠性、并发、国际化和集成场景保留相应类型/标签。无障碍、视觉和性能审查另留专项证据。

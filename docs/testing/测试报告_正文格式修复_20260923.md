# PaperGuard 正文格式修复测试报告

测试日期：2026-09-23  
项目：`/Users/a1234/Documents/perpetual/paperguard`  
验证范围：DOCX 导入、正文编辑保存、模板套用及网页导出。

## 缺陷与修复

导入器此前把 Word 段落里的每个文字 run 都转换成独立内容块，导出器又为每个内容块新建 Word 段落，造成正文断裂、英文缩写被拆开、首行缩进重复。导入器现在按原 Word 段落合并相邻同格式 run，并保留粗体、斜体、下划线、突出显示及上/下标；自动保存仅在行内 run 拼接文本与段落正文相同的情况下保留该格式。空的 `inline_runs` 不改变旧项目哈希。

真实原稿的第一个正文表格还带有源文件批注锚点，而选用模板包没有对应的 `comments.xml`，导致导出 DOCX 无法被 LibreOffice 打开。导入时现对表格 XML 副本移除批注锚点，保留表格本身与原稿不变。

结构对照：原稿有 241 个非空段落；旧网页导出稿有 1,485 个非空段落、1,486 个 run；修复后网页导出稿为 211 个非空段落。定稿参照有 315 个非空段落、4 个表格、27 个图片部件。原稿与定稿的内容版本不同，段落数和页数不要求完全相等；导出稿比定稿少 8 个图片部件也可能来自不同修订内容及模板资源。

对照 PDF 页面的段落缩进、行距和章节位置：修复后导出稿正文段落维持模板的段落格式，旧稿 run 拆段问题消失。两份 PDF 都在本地 LibreOffice 字体环境中缺少部分中文字体，视觉图中的中文字符无法完整显示，因此本次页面复核确认了结构和排版位置，但不能据此评定中文字体字形。LibreOffice 导出时动态目录域仍显示空白；DOCX 设置了打开时更新域，最终使用前应在 Word 中更新目录域并核对中文字体和页码。

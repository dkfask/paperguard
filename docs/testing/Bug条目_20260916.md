# PaperGuard 回归 Bug 条目

## BUG-REAL-004

- **标题**：可用模板删除操作触发页面错误边界
- **严重程度**：S1
- **状态**：已验证关闭
- **类型**：`CODE-REGRESSION`
- **发现方式**：用户反馈 + 前端组件回归测试
- **环境**：Vitest 5 + jsdom，管理员角色，模拟可用自定义模板

### 复现步骤

1. 使用管理员或已认证教师账号进入“模板与排版”页面。
2. 在“可用模板”列表中选择一个非系统模板。
3. 点击该模板右侧的删除按钮。

### 预期行为

打开删除确认框；确认后调用删除接口并刷新可用模板列表。

### 实际行为

点击删除按钮即触发 `TypeError: t is not a function`，页面进入错误边界并显示“页面暂时无法显示”。删除请求未发出。

### 证据

- 修复前 `frontend/tests/Templates.test.js` 稳定复现 `TypeError: t is not a function`。
- 修复后同一回归用例通过；前端全量测试 30/30 通过。
- 根因位置：`frontend/src/views/Templates.vue:311-315`。

### 根因分析

**Verified（E3）**：`remove(t)` 的参数 `t` 覆盖了 `useI18n()` 返回的翻译函数 `t`。点击删除时，`t('templates.deleteTitle', ...)` 实际调用的是模板对象，抛出 `TypeError`，由 `AppErrorBoundary` 接管显示错误页面。

### 影响范围

- **功能面**：可用模板列表中的自定义模板删除入口不可用；模板创建、编辑和系统模板展示不受此变量冲突影响。
- **数据面**：删除请求未发出，不产生错误删除或数据损坏。
- **用户面**：管理员和已认证教师的模板维护删除路径受影响；普通浏览用户没有删除入口。
- **安全面**：未发现权限绕过或敏感数据暴露，后端权限校验未改变。
- **修复波及面**：仅修改前端删除处理函数的局部变量命名，并新增模板删除组件回归测试。

### Severity 依据

模板删除属于管理旁路功能，失败会阻断该操作并触发页面级错误边界，但不影响论文写作主路径，按 S1（核心旁路不可用）定级。

### 修复建议

已将删除处理函数参数改名为 `template`，避免覆盖翻译函数；删除确认、接口调用和列表刷新逻辑保持不变。

### 回归建议

- `frontend/tests/Templates.test.js`：删除按钮打开确认框且不触发页面级错误。
- `frontend/tests/Templates.test.js`：确认删除调用正确模板 ID，并刷新模板列表。
- `backend/tests/test_writing_api.py::test_create_and_update_template`：删除接口返回 204。
- 前端全量 Vitest、类型检查和生产构建。

# Word 导出一致性技术设计

日期：2026-10-23
关联方案：[Word导出一致性补齐方案_20261023.md](./Word导出一致性补齐方案_20261023.md)

## 1. 设计结论

导出路径采用“源模板包 + 明确锚点 + 成品复检”的策略。系统只修改已经确认的内容节点，其他 OOXML 部件从冻结的源模板包保留。

当前代码已有锚点渲染雏形，但并非所有通用导出都会使用它：

- 有锚点且不是 `legacy_adapter` 时，通用渲染器走 `render_anchored_docx`；
- `legacy_adapter` 或无锚点时，可能进入旧的结构重建导出；
- 旧导出器在内容发生变化时会清空正文并按项目结构重建，不能用于复杂表格、多分节或复杂页眉页脚模板的一致性承诺；
- 当前锚点模型没有稳定的表格单元格选择器；
- 当前成品检查器尚未完整比较源模板与成品的表格网格、页眉页脚引用和逐节映射。

因此，未完成稳定映射的复杂模板只能处于 `CONDITIONAL` 或 `BLOCKED`，不能静默降级到旧重建路径。

## 2. 领域边界

### 2.1 模板版本

模板版本是不可变输入，至少绑定：

```text
template_id
template_version
template_definition_hash
source_template_sha256
renderer_version
inspector_version
```

源文件在排队、生成、发布和下载时都要校验摘要。模板源文件变化后必须重新解析、重新准入和重新生成。

### 2.2 锚点服务

`backend/app/services/docx_anchors.py` 只负责 OOXML 节点定位和受限修改，不负责项目业务编排或准入决策。

锚点必须包含稳定选择器和允许的变更范围：

```json
{
  "id": "cover.student_name",
  "kind": "table_cell",
  "part": "word/document.xml",
  "table_index": 0,
  "row": 3,
  "cell": 1,
  "content_control_id": null,
  "occurrence": 0,
  "replacement": "plain_text",
  "source_fingerprint": "..."
}
```

重复或歧义选择器必须在模板发布前拒绝。`occurrence` 不能只用于计数，渲染和复检必须定位到同一个节点。

### 2.3 渲染器

`backend/app/services/generic_docx_renderer.py` 负责选择渲染策略、冻结输入、调用锚点适配器、处理新增媒体资源并返回临时产物。

渲染策略明确分为：

- `source_template_strict`：只允许完整映射的源模板保留式修改；
- `legacy_adapter`：兼容旧模型的结构重建，仅允许在明确标记为兼容输出时使用，不能声明源模板结构保留一致。

当严格路径失败时不得自动降级为 `legacy_adapter`。

### 2.4 导出服务

论文和通用文档保留各自的领域检查器，但共享以下产物流程：

```text
冻结源模板和项目快照
  -> 校验源摘要和准入状态
  -> 生成临时 DOCX
  -> 独立读取输出 DOCX
  -> 源/成品结构差异检查
  -> 领域内容和格式检查
  -> 身份绑定与输出摘要
  -> 原子发布
```

检查失败、检查异常和无法验证都不能发布或下载。

## 3. 源模板结构清单

准入阶段生成只读 inventory，并绑定源模板摘要。每个对象有稳定路径和能力状态：

```json
{
  "status": "conditional",
  "structures": [
    {
      "kind": "table",
      "path": "word/document.xml/table[1]",
      "rows": 6,
      "columns": 2,
      "mapping_status": "partial",
      "review_required": true
    },
    {
      "kind": "header",
      "path": "word/header2.xml",
      "mapping_status": "preserved_only",
      "review_required": true
    },
    {
      "kind": "section",
      "path": "word/document.xml/sectPr[6]",
      "mapping_status": "unmapped",
      "review_required": true
    }
  ]
}
```

能力状态使用：

- `supported`：能够定位、修改或检查；
- `conditional`：能够保留，但需要映射或人工确认；
- `manual_only`：只能记录并要求 Word/WPS 验收；
- `blocked`：无法安全保留或无法建立唯一映射。

当前上传模板的目标清单至少应包含：一张封面信息表、7 个页眉部件、2 个页脚部件和 9 个分节布局。

## 4. 成品差异检查

新增或扩展共享的包级检查器，比较源模板包和输出包的语义差异，而不是要求所有 XML 字节完全相同。

### 4.1 必检结构

- DOCX 包部件和内容类型；
- `word/document.xml` 的表格数量、行列网格、合并关系和边框；
- 页眉页脚部件、分节引用、文本、字段和媒体；
- 分节数量、顺序、页面尺寸、方向、页边距、分页类型和页码引用；
- 样式、编号、图片、媒体和关系文件；
- 锚点替换后的目标值、顺序和完整性。

### 4.2 允许变化

允许变化只能来自声明的锚点和必要的新增资源：

- 锚点内的文本或内容控件值；
- 明确声明的图片、媒体和关系新增；
- 目录或页码域的更新结果；
- 输出报告自身的身份和摘要记录。

未命中锚点、未声明的 XML 修改、结构数量变化或关系漂移都返回 `fail` 或 `unverifiable`。

未修改的包部件应直接透传源字节，避免无意义的 XML 重新序列化。发生修改的 story 部件单独进行规范化比较。

## 5. 准入和导出契约

### 5.1 准入报告

兼容现有字段，同时新增：

```text
status: supported | conditional | blocked
capabilities[]
structures[]
review_required
reviewer
reviewed_at
decision
```

阻断信息必须包含 `code`、`message`、`path`、`object_id` 和修复建议。

### 5.2 成品报告

沿用当前身份绑定字段，并增加源/成品结构规则：

```text
source.table_count/grid/merge/map
header_footer.references/content/fields
section.count/order/layout/break_type/refs/page_number
package.relationships/media/content_types
```

每条检查都必须包含 `rule`、`status`、`object`、`expected`、`actual` 和 `evidence`。`unverifiable` 与 `fail` 都禁止合规下载。

## 6. 入口接入

论文入口：

- 同步导出；
- 异步导出任务；
- 工作流归档及归档下载。

通用文档入口：

- 同步渲染；
- 异步渲染任务；
- 成品下载。

所有入口统一执行冻结、临时生成、成品复检、原子发布和下载时复核。归档下载必须检查 ZIP 内 `final.docx`，不能把 ZIP 本身交给 DOCX 检查器。

## 7. 测试设计

### 7.1 单元和服务测试

- 表格单元格选择器、合并单元格和重复 selector；
- 页眉页脚字段、图片、空部件和不同首页/奇偶页；
- 9 分节的页面设置、引用关系和顺序；
- 未修改部件字节透传和修改部件语义差异；
- 源摘要变化、输出篡改、旧报告复用和任务重试。

### 7.2 API 回归

- 论文同步、异步、归档三条入口使用同一策略；
- 通用文档同步、异步和下载使用同一策略；
- `force` 不能绕过成品检查；
- 失败、异常和 `unverifiable` 均不能下载或归档成功。

### 7.3 ego-lite 和 Word/WPS

ego-lite 验证上传、结构清单、字段映射、条件创建、导出状态和失败门禁。

Word/WPS 验收验证：

- 更新目录和页码域；
- 检查页眉页脚显示；
- 检查 9 个分节分页、边距和方向；
- 检查表格跨页、单元格内容和裁切；
- 检查字体替换、图形和内容溢出。

ego-lite 和 XML 检查只能产生自动化证据，不能把 Word/WPS 验收状态标记为已通过。

## 8. 实施顺序和停止条件

1. 先实现源模板 inventory、表格单元格选择器和三态准入报告；
2. 再实现严格源模板渲染，并禁止失败后降级旧重建路径；
3. 扩展源/成品包级差异检查；
4. 统一所有导出、归档和下载门禁；
5. 使用当前真实模板执行 ego-lite 回归；
6. 由导师在固定 Word/WPS 环境完成视觉验收。

在每个切片的本地测试和门禁通过前，不标记该切片完成。合入、部署和真实 Office 验收分别记录，不用其中一个替代另一个。

> 状态：**design_ready**（本文件是规格，不是实施结果）。
> 日期：2026-10-01（Asia/Shanghai）。阶段：G0。依赖：无。上游：`saas-platform-design-20261001.md` 第 22.2、23.1、26 节。
> 授权边界：本规格**不授权**任何生产写入、任务重试、commit、push、merge、部署或凭据获取。所有交付物默认只读生成。

## 1. 目标与完成定义

W-01 的唯一目的是**在写第一行租户代码之前，把"现在到底是什么状态"变成可核对的事实**，并把技术选型从"建议"变成"有替代方案和验证计划的决策"。

沿用总设计第 23.1 行的完成定义：**基线、缺陷分类、只读迁移报告和授权边界明确**。拆为四个可独立验收的判据：

| 判据 | 含义 | 状态 |
|---|---|---|
| D1 基线冻结 | 仓库身份、schema 版本、运行数据根、release 标记、备份位置、未提交工作全部记录在案且可复现 | NOT STARTED |
| D2 缺陷分类 | 每一个现存失败被归入 `PRODUCT_DEFECT` / `TEST_DEFECT` / `FLAKY` / `ENVIRONMENT` / `BASELINE_EXPIRED` / `DEFERRED`，无"未分类" | NOT STARTED |
| D3 授权边界 | U-09、历史归属映射、旧 admin 平台映射三项各自写明"需要谁批什么" | NOT STARTED |
| D4 ADR 决议 | ADR-01～ADR-08 每条有 ACCEPTED / REJECTED / DEFERRED 结论与验证计划 | NOT STARTED |

**W-01 未全部满足 D1～D4 前，W-02 不得进入 DDL 编写。** 唯一例外：`ADR-02`（PostgreSQL 选型）可与 W-02 的接口设计并行，其余必须先定。

### 2.2 数据库与迁移机制现状

| 事实 | 取证 |
|---|---|
| 单文件 SQLite，`Store` 类直接持有连接 | `backend/app/db.py:72`、`backend/app/db.py:80` |
| 迁移账本存在但**不是版本化迁移** | `backend/app/db.py:29`（`SCHEMA_MIGRATIONS` 为硬编码 10 项字符串元组）、`backend/app/db.py:453`（无条件 `INSERT OR IGNORE` 全部版本） |
| DDL 在 **`Store()` 构造时**执行，不是迁移命令 | `backend/app/db.py:78`（`__init__` 调 `_init_schema()`） |
| CLI `migrate` 只校验账本条目是否齐全，不执行任何版本化脚本 | `backend/app/cli/migrate.py:19-27` |
| 表数量 | 24 张业务表 + `schema_migrations` |
| 全部业务对象以 JSON 文本存储的表 | `templates` / `projects` / `requirement_sets` / `document_packages` / `document_projects` / `validation_runs` / `organization_units` / `check_runs` / `policy_audit_events` / `workflow_records` |
| 组织树整棵存在 JSON 列里，无外键、无索引 | `backend/app/db.py:254`（`organization_units(id, data, updated_at)`）、`backend/app/models/organization.py:16`（`parent_id` 是 JSON 内字段） |

**关键判断（已验证）**：当前机制是"**幂等建表 + 账本打标**"，不是"版本化迁移"。账本记录"已应用"与"DDL 实际做了什么"之间**没有对应关系校验**——`INSERT OR IGNORE` 会让账本在 DDL 被跳过时同样显示完整。这正是总设计第 271 行"不要继续把 DDL 隐式放在启动过程"所指的现状。

## 3. 任务分解

### T-01.1 基线冻结（M0）

**做**：生成一份 `docs/evidence/W-01-基线_20261001.md`，包含并**逐项给出取证命令与输出**：

1. `git rev-parse HEAD`、分支名、`git rev-list --left-right --count origin/<branch>...HEAD`
2. `git status --porcelain` 全量输出（区分已跟踪改动 / 未跟踪 / 用户 `docs/testing/` 3 文件）
3. `python -c "from app.db import SCHEMA_MIGRATIONS, Store; ..."` 打印当前 `schema_migrations` 账本实际内容与 24 张表的 `sqlite_master` 清单
4. `data_dir()` 的**实际解析结果**（当前实现见 `backend/app/db.py:43-53`），以及归档目录、附件目录、DB 文件三者的实际路径与是否同属一个备份域
5. 生产侧**只读**：`current-release` 标记文件内容、systemd 单元是否 `is-enabled`、`/etc/paperguard/paperguard.env` **只核对键名不读值**
6. 备份存在性：备份目录、代数、校验摘要；**不得为验证而触发备份或恢复**

**不做**：不 `git add`、不 commit、不写生产、不触发备份任务。

**DoD**：任一事实都能用记录里的命令原样复现；`docs/testing/` 3 个用户文件在 §2 状态中出现且标注"保持原状，不修改"。

## 5. 负面测试要求

W-01 本身是只读工作，但**必须先证明"只读"成立**，否则它的产出不可信：

1. 在库文件上跑完 T-01.1 全部命令后，比对 DB 文件 mtime 与 size 未变

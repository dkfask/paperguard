# PaperGuard 商业化范围与放行条件

日期：2026-09-30。范围由本次用户指令推进；商业规则尚未裁决，本文不授权收费或生产业务写入。
配套：[未决项](../evidence/未决项_20260913.md)。既有商业设计与需求模型是本机讨论背景，
按原有 ignore 规则不提交；本文独立定义本轮范围和放行条件。

## 1. 当前底座和明确缺口

| 能力 | 当前事实 | 不能推导的结论 |
|---|---|---|
| 教学闭环 | 写作、检查、提交、审核、消息和归档已有实现与阶段性证据 | 不代表所有学校样本及峰值 UAT 已通过 |
| 多学校运行 | 一套部署服务多个学校；AI 默认配置已有学校维度与全局回退 | 组织节点不等于合同租户，未证明全资源多租户放行 |
| AI 治理 | 次数配额、用量记录、供应商配置隔离、披露、审计和熔断 | 不是余额、token 成本、支付或财务流水 |
| 异常恢复 | 隔离源副本中完成新进程重启、持久任务、消息和备份故障演练 | 不是生产停机演练、生产备份恢复或 RPO/RTO 承诺 |
| 支付收费 | 尚未实现且本次不启用 | 不承诺已有套餐、充值、订阅、发票或自动对账 |

## 2. C0：非付费试点运营（下一实施范围）

C0 不改变现有角色权限，不启动支付，不把教师或学生账号直接当成计费主体。

1. **客户启用清单**：明确学校负责人、管理员、试点周期、组织范围、模板、保留规则和退出联系人。
2. **权益独立建模**：明确平台 AI、BYOK、导出等权益，与 admin/teacher/student 的业务权限分离；
   暂停 AI 不应导致用户无法访问其已有论文或约定范围的数据导出。
3. **用量看板**：补齐学校作用域的只读查询与管理界面，分别显示尝试次数、成功、失败、熔断拒绝；
   不显示其他学校身份、正文、供应商密钥，不使用现有字符数伪造 token 成本。
4. **机构预算规则**：现在只有每用户调用次数控制；机构总额、学校级参数覆盖和超额体验作为待实施项，
   不声称现有配额已经能控制学校总费用。
5. **支持与退出**：列出问题接收、处理责任、数据下载和删除申请流程；不得未获授权物理删除用户数据。

C0 放行条件：最新 CI 全绿；真实管理员审计验证完成；试点组织与权益边界验证通过；
生产凭据保护达标；学校间授权矩阵验证通过；负责人接受实际验证边界。
微信入口若不在试点范围可显式排除，否则必须有真机与真实 provider 证据。

## 3. C1：权益与账务核心（商业规则裁决后实施）

### 3.1 开工前需要裁决

| 决策 | 待确认内容 | 未裁决时的边界 |
|---|---|---|
| 合同与计费主体 | 个人、学校或学院；组织与合同租户的映射 | 不给用户创建可扣款余额 |
| 收费单位 | 次数、token、固定许可或混合；货币与精度 | 不将字符数或请求次数当金额 |
| 免费额度 | 额度归属、周期、结转与超额行为 | 不擅自赠送商业额度或定价 |
| BYOK | 是否收费；平台服务费与供应商成本的关系 | 不混入平台供应商成本 |
| 失败与超时 | 已发出但结果未知、失败是否收费、对账窗口 | 不自动退款或再次扣款 |
| 商业期限 | 试用结束、合同到期、降配、暂停与数据导出 | 不冻结已有业务数据 |
| 支付渠道 | 主体、渠道、收款账户、回调和退款权限 | 不创建支付订单或连接真实收款 |

### 3.2 账务必须满足的技术边界

- 合同租户、业务组织、业务角色和权益分别建模，所有服务端查询强制作用域。
- 请求 ID / 幂等键贯穿预留、供应商调用、结算与对账；审计与财务流水不放密钥或正文。
- 账务流水不可变，金额用整数最小货币单位；余额变更与流水同事务，不能写入项目 JSON。
- 先预留、再按已裁决规则结算；未知结果进入待对账，不能直接当失败退款或再次执行。
- 现有 `ai_usage` 的 `upstream_error` 混合了上游失败与未发出的熔断拒绝，接收费前应拆分
  **attempt / dispatched / rejected / completed / unknown**，保留历史而不是重写既有记录。
- 明确审计事件与请求的关联规则；当前通用审计契约允许空 `request_id`，收费链路不能沿用此弱约束。
- 主密钥缺失时的兼容明文路径不能作为商业部署默认；主密钥轮换、原密钥保管与恢复另设验收。

### 3.3 C1 最小验收矩阵（尚未执行）

1. 两个合同租户、多角色及跨组织直接 ID 访问，均不能越权读写权益或账务。
2. 同一幂等请求重复及并发提交仅预留、结算一次。
3. 熔断拒绝未调供应商，单独记尝试和拒绝，账务按已裁决规则处理。
4. 调用后超时或连接丢失进入未知状态，对账前不得重复扣费或自动释放。
5. BYOK 与平台默认模型分别核算，失败不导致其他租户余额变化。
6. 每一笔账务都能关联请求、操作者、权益版本及结果；审计不能含密钥或正文。
7. 备份与恢复保持账务、业务记录及附件同一代数据，不制造余额或重复流水。

## 4. C2：支付和商业运营（独立授权）

在 C1 账务矩阵通过、商业主体和价格确定后，再实施套餐、试用、支付回调、退款/冲正、
发票或收据、对账和合同到期体验。先用渠道测试环境及合成订单验收，真实收款、退款和发布
分别授权。技术治理修复或披露页面存在不能替代法律、合同或监管合规确认。
